# Фразы для прочтения и временное распознавание

Этот выпуск подготовлен в ветке `fix/reading-text-feedback`. Commit/push/merge выполняет пользователь. На сервере изменения ещё не применены.

## Поведение

- Участник в «Прочтении» раскрывает «Опечатка или проблема с фразой?», предлагает текст и/или отправляет сообщение. Комментарий необязателен. Повторный репорт одного участника не дублируется, пока первый рассматривается. Фраза больше не предлагается этому участнику до рассмотрения.
- Редактор/соредактор открывает «Сообщения о фразах» из проверки озвучек. Можно применить исправление, снять фразу с записи или закрыть сообщение. Участник сам общий текст не меняет.
- Миграция заполняет снимок текста существующих записей текущим текстом фразы. Для будущих записей текст сохраняется в момент отправки. Если во время записи редактор уже изменил фразу, сервер просит обновить страницу и записать заново. Старые вкладки без нового поля также попросят обновление.
- Экспорт принятых озвучек берёт снимок текста, сохраняет speaker_id и остаётся отдельным от расшифровок клипов.
- Демо: микрофон до 5 секунд, загрузка до 10 секунд, максимум 15 МиБ (15 × 1024² байт). Формат определяется декодером FFmpeg, а не доверенным расширением. Слишком длинные файлы отклоняются.
- Аудио демо не сохраняется в постоянное хранилище. FFmpeg использует временную папку, удаляемую при завершении/ошибке. Django временные upload-файлы закрываются при завершении запроса. В БД остаются только результат и метаданные для лимита 15 попыток за 24 часа; они удаляются по таймеру после 24 часов. Корпусные записи «Прочтения» сохраняются как прежде.

## Выпуск на Ubuntu (после merge)

Выполнить в SSH, не в локальном Anaconda Prompt. Сначала сохранить свежий бэкап и скачать его на ПК обычным способом. Перед миграцией сайт останавливается, чтобы снимки существующих текстов были согласованными.

```bash
cd /opt/avar
git pull --ff-only origin main
sudo docker compose -f docker-compose.production.yml build web
sudo bash deploy/backup.sh
```

После подтверждения скачанного бэкапа:

```bash
cd /opt/avar
sudo bash deploy/update_asr_service.sh
sudo docker compose -f docker-compose.production.yml stop caddy web
sudo docker compose -f docker-compose.production.yml run --rm web python manage.py migrate --noinput
sudo docker compose -f docker-compose.production.yml run --rm web python manage.py purge_asr_trials
sudo docker compose -f docker-compose.production.yml --profile public up -d --no-deps web caddy
```

Команда purge удаляет все сохранённые аудио предыдущего демо, включая оставшиеся файлы в отдельной папке `ASR_TRIAL_ROOT/asr_trials`. Она не обращается к recordings/media корпуса. Исторические архивы резервных копий не переписываются: если в них были старые демофайлы, они останутся внутри этих архивов.

После запуска:

```bash
cd /opt/avar
sudo docker compose -f docker-compose.production.yml exec -T web python manage.py site_preflight
curl -I --max-time 20 https://audio.avar.me/login/
```

Дождаться HTTP 200 после старта Gunicorn. В браузере проверить загрузку 6–10-секундного файла, отклонение файла длиннее 10 секунд/15 МиБ, запись микрофона, сообщение о фразе и рассмотрение редактором. В `private_asr_trials/asr_trials` не должно появляться новых аудиофайлов. Действующий таймер purge оставить включённым: теперь он очищает старые метаданные и остатки демо, не хранит аудио двое суток.

Сервис ASR обновляется из отслеживаемого `deploy/asr_service`, веса и n-грамма не меняются. Скрипт при неудачной проверке запуска возвращает предыдущий контейнер. При успешном запуске старый остановленный контейнер сохраняется для отката. Скрипт рассчитан на текущие пути, пользователя ubuntu и сеть avar_default.
